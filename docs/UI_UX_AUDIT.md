# DIB Android UI·UX 및 정책 점검

최종 점검일: 2026-09-16

이 문서는 현재 Android 앱 구현을 기준으로 화면 비율, 정보 위계, 상호작용, 접근성, 서비스 정책을 점검한 결과다. 디자인 기준은 Figma `01_Wireframe/full`이고, 동작과 정책은 최신 합의 사항을 우선한다.

## 이번 점검에서 바로 반영한 항목

- 시작 화면의 고정 높이 이미지를 반응형 비율로 변경하고 세로 스크롤을 지원했다.
- 시작 화면의 행동 위계를 `이메일로 시작하기 → 로그인 → 비회원 둘러보기` 순으로 정리했다.
- 아직 사용할 수 없는 카카오 로그인을 진입 화면의 주 행동에서 제거했다. 로그인 화면에서는 비활성 상태와 이유를 함께 표시한다.
- 실제 진행률로 오해할 수 있던 스플래시의 고정 `64%` 표시를 불확정 로딩 표시로 변경했다.
- 상품 상세와 상품 개요의 대표 이미지를 화면 너비 기반 비율로 변경했다.
- 이미지 뷰어가 `560dp`에 고정되지 않고 남은 화면을 사용하며 원본 비율에 맞춰 보이도록 변경했다.
- 사진 추가, 새 방송, 인증 완료, 경고 표시에 사용하던 문자 기호를 같은 굵기의 벡터 아이콘으로 교체했다.

## 화면 위계 기준

- 화면 제목은 한 화면에 하나만 강하게 표시한다. 섹션 제목, 상태, 보조 설명은 각각 한 단계씩 낮춘다.
- 주요 행동은 화면당 하나를 원칙으로 하고 네이비 채움 버튼을 사용한다. 보조 행동은 외곽선 또는 텍스트 버튼을 사용한다.
- 카드 안에서는 `상태 → 상품명 → 가격/시간 → 행동` 순서로 읽히게 한다.
- 이미지 영역은 화면 높이 고정값 대신 `aspectRatio` 또는 가용 영역을 사용한다.
- 경매 종료가 임박하면 색만 바꾸지 않고 아이콘, 남은 시간, 행동 문구를 함께 바꾼다.
- 목록의 찜은 `favorite_outline`과 `favorite_selected`만 사용하고 별도 `찜` 문구를 반복하지 않는다.

## 확인된 정책과 현재 구현

| 영역 | 정책 | 현재 상태 |
|---|---|---|
| 상품 등록 | 등록 직후 검수 대기, 승인 후 경매·Live 편성 가능 | 반영됨 |
| 일반·Live 입찰 | 첫 입찰 전에 경매당 고정 보증금 1,000원 결제 | 화면과 입찰 흐름에 반영됨 |
| 판매자 경매 시작 | 경매 시작 전에 고정 보증금 1,000원 결제 | **서버 계약 확인 필요** |
| 경매 연장 | 종료 30초 이내 유효 입찰마다 15초 연장 | 안내와 긴급 UI에 반영됨 |
| 본인 경매 입찰 | 판매자는 자신의 경매에 입찰 불가 | 반영됨 |
| Live 편성 | 승인된 본인 상품, 최대 10개, 동시 경매 1개 | 관리 화면에 반영됨 |
| 비회원 Live | 채팅·상세·입찰·찜·신고 사용 불가 | 인증 유도 흐름 적용됨 |
| 결제 | 낙찰 즉시 등록 결제수단으로 낙찰가 전액 자동 결제 | 거래 상태 화면에 반영됨 |

판매자 보증금은 현재 프론트엔드 저장소와 공유 명세에서 결제 준비·승인·조회 API를 찾을 수 없다. 버튼만 결제처럼 보이게 만들면 실제 결제 없이 경매가 시작될 수 있으므로 임의 구현하지 않는다. 백엔드 계약이 확정되면 `결제수단 선택 → 1,000원 결제 → 승인 확인 → 경매 시작` 순서로 연결해야 한다.

## 다음 시각 검수 항목

- 작은 화면, 큰 글꼴, 가로 회전에서 잘림과 터치 영역을 확인한다.
- 홈 카드형·목록형과 내 거래 목록의 이미지 비율, 여백, 상태 배지 높이를 같은 기준으로 맞춘다.
- Live 영상 위 댓글 대비, 키보드 표시 시 입력창 위치, 상품 목록 최대 높이와 내부 스크롤을 실제 기기에서 확인한다.
- 네트워크 지연·빈 목록·오류·재시도·세션 만료 상태를 화면별로 확인한다.
- 디버그 둘러보기는 샘플 데이터임을 유지하고 실제 결제·송출 성공으로 오해되는 표현을 사용하지 않는다.

현재 ADB 기기가 `unauthorized` 상태라 이번 변경은 코드·빌드·정적 검사까지 검증하고, 실제 픽셀 단위 시각 검수는 기기 인증 후 이어서 진행한다.
