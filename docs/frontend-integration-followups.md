# 프론트 연결 후속 확인

백엔드와 실시간 연결 작업이 끝난 뒤 아래 항목을 다시 확인한다. 화면 컴포넌트만으로 정확하게 처리할 수 없는 상태·계약 의존 항목이다.

## Live 송출과 피드 영상

- 판매자 방송 화면은 `prepareStream` 응답으로 LiveKit Room에 연결하고 카메라·마이크를 발행한다. 카메라는 1080p·30fps를 목표로 캡처하며 시청 피드는 최고 품질 simulcast 레이어를 우선 수신한다.
- Live 피드는 현재 보이는 방송의 시청 토큰을 자동 발급해 LiveKit 원격 영상을 바로 구독한다. 별도 시청 화면 진입은 필요하지 않다.
- 세로로 다음 방송을 넘기면 이전 Room을 해제하고 새 방송 Room에 연결한다. 화면에는 영상을 비율 유지 확대(crop)해 가득 표시한다.
- 채팅·입찰은 기존 WebSocket 연결을 유지하며 영상 연결 실패와 독립적으로 동작한다.
- 방송 중 상품 경매가 열리거나 닫혀도 Live WebSocket과 LiveKit Room은 다시 만들지 않고 경매 토픽만 교체한다. 상품·연결 상태·영상이 점멸하지 않아야 한다.
- 앱이 백그라운드에서 돌아오면 현재 화면을 유지한다. 프로세스가 다시 만들어진 경우에는 마지막 로그인 화면을 복원하되, 판매자의 진행 중 방송이 있으면 해당 방송 콘솔을 최우선으로 연다.
- 실제 두 기기 환경에서 토큰 만료, 네트워크 전환, 판매자 카메라 재시작 뒤 재구독 동작을 추가 검증한다.

## 입찰 이력과 마감 상태

- 실시간 입찰 성공 이벤트는 현재가와 최고 입찰 상태만 갱신한다. 상세 화면의 `bidHistory` 목록은 별도 조회 결과라 즉시 추가되지 않는다.
- 입찰 성공 이벤트 수신 후 이력 재조회 또는 이벤트 항목 병합 중 한 방식을 정하고 중복 이벤트 키로 중복 추가를 막는다.
- 내 거래 입찰 DTO에는 상품 이미지·상품명·남은 시간이 없어 실시간 마감 강조와 실제 썸네일을 만들 수 없다. 백 연결 후 경매 요약 조합 또는 응답 필드 확장이 필요하다.

## 상품 등록 결과

- 실제 상품 등록 완료 화면의 상품 번호는 서버가 반환한 `productId`다.
- `PREVIEW-001`은 개발 미리보기에서만 사용하는 값이며 사용자 화면에서는 번호처럼 표시하지 않는다.

## 통합 후 회귀 확인

- LIVE 댓글, 신고 버튼, 경매 상품 패널이 작은 화면과 키보드 표시 상태에서 겹치지 않는지 확인한다.
- Live 상품 경매 시작·종료 때 판매자와 시청자의 영상 및 연결 상태 문구가 점멸하지 않는지 확인한다.
- 방송 콘솔에서 Android 홈으로 나갔다 돌아왔을 때 같은 콘솔이 유지되고, 앱 프로세스를 다시 시작해도 진행 중인 본인 방송으로 복귀하는지 확인한다.
- 일반 경매와 LIVE 입찰의 `+1,000원`, `+5,000원`, `+10,000원`이 최신 현재가를 기준으로 계산되는지 확인한다.
- 종료 60초 이하에서 홈, 상세, LIVE, 내 거래의 긴박한 상태 표현이 동일한 실시간 값으로 전환되는지 확인한다.
