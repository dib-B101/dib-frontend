# 프론트 연결 후속 확인

백엔드와 실시간 연결 작업이 끝난 뒤 아래 항목을 다시 확인한다. 화면 컴포넌트만으로 정확하게 처리할 수 없는 상태·계약 의존 항목이다.

## Live 판매자 방송 화면

- `SellerLiveStudioScreen`에 카메라·마이크 권한 요청, LiveKit Room 연결과 발행, 로컬 영상, 방송 시간, 음소거, 카메라 전환, 상품 경매 시작 및 종료 UI를 구현했다.
- 앱에 LiveKit Android SDK와 카메라·마이크 권한을 추가했다.
- `feature/api-contract-sync`가 `/live-broadcasts/{id}/token` 응답을 `serverUrl`, `token`, `roomName`, `participantName`으로 동기화하고 있으므로 해당 변경이 `develop`에 병합된 뒤 화면 내비게이션을 연결한다.
- 관리 화면의 `Live 시작`은 판매자 스튜디오로 이동해야 하며, 스튜디오가 LiveKit 발행에 성공한 뒤 방송 시작 상태를 확정해야 한다.
- 연결 실패 시 관리 화면의 방송 상태를 `LIVE`로 바꾸지 않고 스튜디오에서 재연결할 수 있어야 한다.

## 입찰 이력과 마감 상태

- 실시간 입찰 성공 이벤트는 현재가와 최고 입찰 상태만 갱신한다. 상세 화면의 `bidHistory` 목록은 별도 조회 결과라 즉시 추가되지 않는다.
- 입찰 성공 이벤트 수신 후 이력 재조회 또는 이벤트 항목 병합 중 한 방식을 정하고 중복 이벤트 키로 중복 추가를 막는다.
- 내 거래 입찰 DTO에는 상품 이미지·상품명·남은 시간이 없어 실시간 마감 강조와 실제 썸네일을 만들 수 없다. 백 연결 후 경매 요약 조합 또는 응답 필드 확장이 필요하다.

## 상품 등록 결과

- 실제 상품 등록 완료 화면의 상품 번호는 서버가 반환한 `productId`다.
- `PREVIEW-001`은 개발 미리보기에서만 사용하는 값이며 사용자 화면에서는 번호처럼 표시하지 않는다.

## 통합 후 회귀 확인

- LIVE 댓글, 신고 버튼, 경매 상품 패널이 작은 화면과 키보드 표시 상태에서 겹치지 않는지 확인한다.
- 일반 경매와 LIVE 입찰의 `+1,000원`, `+5,000원`, `+10,000원`이 최신 현재가를 기준으로 계산되는지 확인한다.
- 종료 60초 이하에서 홈, 상세, LIVE, 내 거래의 긴박한 상태 표현이 동일한 실시간 값으로 전환되는지 확인한다.
