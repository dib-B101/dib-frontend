# 01_Wireframe 구현 상태

Figma `01_Wireframe`를 화면 모양뿐 아니라 스크롤, 입력, 상태 변화, 바텀시트와 화면 이동을 포함한 Compose 앱 흐름으로 구현합니다.

## 연결된 사용자 흐름

- 인증: 스플래시 → 시작 화면 → 이메일 로그인 → 홈, 로그인 세션 유지와 로그아웃
- 홈: 전체 세로 스크롤, 일반·마감 임박 전환, 실시간 카운트다운, 찜, LIVE·상세 이동
- 카테고리: 8개 카테고리 목록 → 선택 카테고리 상품 결과 → 상품 상세
- 검색·알림: 최근·인기 검색어, 검색 결과, 필터 바텀시트, 결과 없음, 알림 필터
- 라이브 피드: 전체 화면 영상, 팔로우, 찜, 채팅 작성, 상품 목록 바텀시트, 입찰 바텀시트
- 상품 상세: 전체 세로 스크롤, 이미지 뷰어 확대·이동, 판매자·후기·판매 목록, 신고, 찜, 입찰 상회·실패·낙찰 상태
- 입찰 참여: 현재가 초과 금액 자유 입력, 등록 결제수단·배송지 선택, 보증금 없는 입찰과 마감 연장
- 상품 등록: 상품 정보 → 경매 설정 → 등록 확인, 필수 입력 검증과 AI 검수 요청
- 내 거래: 입찰·구매·판매 탭, 입찰 상품 상세, 구매·판매 거래 상세
- 낙찰 거래: 구매자의 결제 실패·재시도·성공 → 상품 준비 → 배송 조회 → 구매 확정, 판매자의 송장 입력 → 배송 → 정산
- 마이: 프로필 수정, 찜한 상품과 빈 상태, 등록 상품 필터, 알림, 문의 등록, 배송지·정산 계좌 추가·수정·기본값·삭제, 알림 설정, 신고 내역, 로그아웃, 탈퇴 제한·완료

## 현재 로컬 상태로 동작하는 부분

- 상품, 입찰, 거래, 채팅과 알림 데이터는 화면 동작을 검증하기 위한 샘플 데이터입니다.
- 자동 결제·재결제와 계좌 확인은 실제 PG·은행 API 대신 로컬 상태 전환으로 동작합니다.
- 실시간 가격, 남은 시간, 라이브 댓글은 API와 소켓 연결 전까지 Compose 상태로 갱신합니다.
- 서버 연결 시 화면 구조는 유지하고 ViewModel의 상태와 이벤트 구현을 교체합니다.

## 서버 연동 때 연결할 실제 처리

- 결제 승인·재시도·중복 결제 방지를 위한 PG 응답
- 동시 입찰 가격 갱신과 입찰 성공 여부를 위한 소켓·서버 응답
- 택배사 배송 조회와 구매 확정 취소 정책
- 이미지 업로드 실패, AI 검수 지연·거부 상세 사유
