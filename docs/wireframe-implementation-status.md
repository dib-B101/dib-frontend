# 01_Wireframe 구현 상태

Figma `01_Wireframe`를 디자인과 상태 정의 기준으로 사용하고, Compose 화면은 스크롤·입력·상태 변화·바텀시트·화면 이동을 포함한 실제 앱 흐름으로 구현한다.

## 구현된 화면 흐름

- 인증: 스플래시, 시작, 로그인, 이메일 찾기, 재설정 링크 발송·새 비밀번호 변경, 회원가입
- 홈·탐색: 세로 스크롤 홈, 카드·목록 보기, 카테고리, 검색·필터, 알림 화면
- 경매: 상세, 전체 이미지 뷰어, 판매자 정보, 찜, 입찰 이력, 실시간 입찰
- 피드·Live: 세로 피드, 투명 댓글, 키보드 위 채팅, 고정 높이 상품 목록, Live 입찰·신고
- 알림: 실시간 수신 목록, 카테고리 필터, 인앱 배너, 경매·Live·거래 화면 이동
- 판매: 상품 등록·수정·삭제, 경매 예약·수정·취소, Live 예약·편성·송출 준비·진행
- 거래: 내 입찰·구매·판매, 주문 상세, 결제, 송장, 배송 확인, 구매 확정, 거래 채팅
- 마이: 프로필, 찜, 내 상품, 배송지, 정산 계좌·내역, 문의·신고, 알림 설정, 탈퇴

## 데이터 동작

서버 URL이 설정된 빌드는 연결된 REST와 WebSocket 데이터를 사용한다. 목록 화면은 cursor 또는 이전 메시지 ID로 추가 데이터를 불러오며, 로딩·빈 상태·부분 실패·재시도를 구분한다. 서버 URL이 없는 개발 빌드만 화면 확인용 샘플을 표시한다.

입찰 바텀시트는 금액을 검증하고 확정된 WebSocket 계약에 따라 `PLACE_BID {commandId,auctionId,amount,sentAt}`를 바로 보낸다. 낙찰 시 서버가 등록된 Toss 빌링키로 낙찰가 전액을 자동결제하며, 실패하면 거래 상세의 재결제 API를 사용한다.

## 외부 계약 대기

- `apiAddressId`를 제공하는 주소 검색 서비스
- 복수 결제수단과 기본 카드 지정 정책
- 입찰·주문 배송지 스냅샷 계약
- 비밀번호 재설정 링크 URI
- 차순위 구매 제안 API
- 유사 상품에서 활성 auctionId를 찾는 계약
- REST 알림 내역·읽음 처리 API
- 판매자 공개 프로필·후기·판매 경매 목록 API
- 실제 Live 송출 SDK와 장애 복구 규칙

세부 endpoint와 검증 순서는 [backend-integration.md](backend-integration.md)를 따른다.
